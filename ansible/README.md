# Ansible Configuration for Nomad Cluster

This directory contains Ansible playbooks and roles to install and configure HashiCorp Nomad on the infrastructure provisioned by Terraform.

## Quick Start

After running `terraform apply`, the inventory file will be automatically generated. Then run:

```bash
cd ansible

# Test connectivity
ansible all -m ping

# Configure the entire cluster
ansible-playbook site.yaml
```

## Directory Structure

```
ansible/
├── ansible.cfg              # Ansible configuration
├── site.yaml                # Main orchestration playbook
├── inventory.ini            # Auto-generated by Terraform
├── ssh_key.pem             # Auto-generated SSH key
├── playbooks/
│   ├── nomad_servers.yaml  # Server configuration playbook
│   └── nomad_clients.yaml  # Client configuration playbook
└── roles/
    ├── common/             # Base system setup
    │   ├── defaults/
    │   └── tasks/
    ├── hashicorp_release/  # HashiCorp binary installer
    │   ├── defaults/
    │   └── tasks/
    └── nomad/              # Nomad installation & configuration
        ├── defaults/
        ├── handlers/
        ├── tasks/
        └── templates/
```

## Playbooks

### site.yaml
Main playbook that configures the entire cluster. It:
1. Gathers facts from all hosts
2. Configures Nomad servers
3. Configures Nomad clients
4. Displays cluster status summary

### playbooks/nomad_servers.yaml
Configures Nomad server nodes with:
- Cloud auto-join enabled (discovers servers via AWS tags)
- Bootstrap expect set to the number of servers
- Telemetry and logging configured
- Systemd service setup

### playbooks/nomad_clients.yaml
Configures Nomad client nodes with:
- Cloud auto-join to discover servers
- Network interface configuration
- Docker driver enabled (if Docker is installed)
- Systemd service setup

## Roles

### common
Base system configuration:
- Installs essential packages (jq, net-tools, ntp, unzip, curl, wget)
- Configures NTP for time synchronization
- Sets hostname based on inventory

### hashicorp_release
Generic role for installing HashiCorp products:
- Downloads binaries from releases.hashicorp.com
- Verifies checksums
- Handles version upgrades
- Supports multiple architectures (amd64, arm64, etc.)

### nomad
Nomad-specific installation and configuration:
- Installs Nomad v1.11.1 by default
- Creates configuration directories (/etc/nomad.d, /opt/nomad/data)
- Generates configuration from Jinja2 templates
- Sets up systemd service
- Configures cloud auto-join for AWS
- Supports both server and client modes

## Configuration Variables

### Nomad Role Variables

Located in `roles/nomad/defaults/main.yaml`:

```yaml
# Binary configuration
nomad_binary_version: "1.11.1"
nomad_binary_checksum: "sha256:a120ba1be96d536ef7196911b57bfbe78fe08c53935dfd16eae0206eba09d729"

# Server configuration
nomad_server_enabled: false
nomad_server_bootstrap_expect: 3

# Client configuration
nomad_client_enabled: false
nomad_client_servers: []

# Cloud auto-join (AWS)
nomad_cloud_auto_join_enabled: false
nomad_cloud_auto_join_tag_key: "Role"
nomad_cloud_auto_join_tag_value: "server"

# ACL configuration
nomad_acl_enabled: false

# Logging
nomad_log_level: "INFO"
nomad_log_file: "/var/log/nomad.log"
```

## Usage Examples

### Configure Entire Cluster
```bash
ansible-playbook site.yaml
```

### Configure Only Servers
```bash
ansible-playbook playbooks/nomad_servers.yaml
```

### Configure Only Clients
```bash
ansible-playbook playbooks/nomad_clients.yaml
```

### Check Connectivity
```bash
ansible all -m ping
```

### Run Ad-Hoc Commands
```bash
# Check Nomad version on all hosts
ansible all -a "nomad version"

# Check server members
ansible servers -a "nomad server members"

# Check node status
ansible clients -a "nomad node status"

# Restart Nomad service on servers
ansible servers -b -m systemd -a "name=nomad state=restarted"
```

### Override Variables
```bash
# Install a different Nomad version
ansible-playbook site.yaml -e "nomad_binary_version=1.10.0"

# Enable ACLs
ansible-playbook site.yaml -e "nomad_acl_enabled=true"

# Change log level
ansible-playbook site.yaml -e "nomad_log_level=DEBUG"
```

## Customization

### Modify Server Configuration
Edit `playbooks/nomad_servers.yaml` to change server-specific settings:
- Bootstrap expect count
- ACL settings
- Log levels
- Cloud auto-join parameters

### Modify Client Configuration
Edit `playbooks/nomad_clients.yaml` to change client-specific settings:
- Server connection methods
- Network interfaces
- Resource limits

### Add Custom Tasks
Add custom tasks to the playbooks' `post_tasks` section or create new roles.

## Important Notes

1. **IAM Instance Profile**: The Terraform configuration creates an IAM instance profile but doesn't attach it to instances. For cloud auto-join to work, you need to attach the instance profile to your EC2 instances.

2. **First Run**: The first playbook run will take several minutes as it downloads and installs Nomad.

3. **Idempotency**: All playbooks are idempotent and can be run multiple times safely.

4. **ACLs**: ACLs are disabled by default. Enable them in production by setting `nomad_acl_enabled: true`.

5. **TLS**: TLS is not configured by default. Consider adding TLS configuration for production use.

## Next Steps

After running the playbooks:

1. Verify cluster formation:
   ```bash
   nomad server members
   nomad node status
   ```

2. Access the Nomad UI at `http://<server-ip>:4646`

3. Bootstrap ACLs (if enabled):
   ```bash
   nomad acl bootstrap
   ```

4. Deploy your first job:
   ```bash
   nomad job run example.nomad
   ```
